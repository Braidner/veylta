# Image pages inside a text PDF: a second vision pass, and a page that says it was not read

**Goal:** A page that carries a picture and almost no text inside a text-layer PDF is read by a
second Codex vision pass and joins the same analysis; when it cannot be read, the document says so
per page instead of staying silent.

**Why:** On a real 11-page laboratory report the proteinogram is a densitometry curve drawn as an
image on page 2, with the word «Протеинограмма» itself rasterised. Because a run sends text or
images and never both, that page was never seen by anything, and nothing in the report said so. The
fractions happened to be printed as text on other pages, so no number was lost this time — the next
document may not be so kind.

**Architecture:** The whole-document choice stays: a PDF with a text layer travels as text. New is a
second, page-scoped run over the pages that the text pass could not read, using the existing vision
path (`--image`, the model transcribes each page first, every fragment binds to that transcription).
Its verified output is merged into the same `ProcessingExtractionOutput` the job completes with, so
one document has one analysis. `document_pages` keeps `UNIQUE (family_id, document_version_id,
page_number)` — an image page's row *becomes* the vision transcription with
`extraction_method = codex_vision` rather than gaining a second row. A failed or skipped second pass
never fails the job: those pages are recorded as unread with a closed, server-derived reason.

**Tech stack:** pdfjs-dist (operator list for raster detection), @napi-rs/canvas, node:sqlite,
Fastify, Next.js.

## Global constraints

- Every fact still cites an exact fragment with a page number, verified against that page's own
  text — a transcription for a vision page, the text layer otherwise. Verification stays per item.
- A run sends text or images, never both. Two runs, each of one kind, is the shape here.
- A rejection reason is always a server-derived code from a closed vocabulary, never a model
  sentence. The same holds for why a page was not read.
- Audit rows stay payload-free. The run journal may carry document content; nothing else may.
- The second pass is best-effort: the text pass's result must survive its failure intact.
- TDD, files under 250 lines, `config/file-length-baseline.json` never hand-edited, UI text
  Russian, code and comments English, synthetic fixtures only, gate under Node 24.19.0 (`.nvmrc`).

## Task A — the primitives that see a picture

**Files:** `packages/contracts/src/documents.ts` (or wherever `DOCUMENT_CONTRACT_VERSION` lives),
`apps/api/src/processing/pdf-text-extractor.ts`, `apps/api/src/processing/document-images.ts`,
their `*.test.ts`, `scripts/` for a synthetic fixture.

1. `ExtractedPageText` gains a per-page fact: the page painted at least one raster image
   (`OPS.paintImageXObject` / `paintInlineImageXObject` / `paintImageMaskXObject` in
   `page.getOperatorList()`), and how many characters of text it yielded. Bound the operator scan
   the way the file already bounds everything else.
2. One exported rule — `imageOnlyPages(pages)` — returns the page numbers that carry a raster image
   and less text than a named threshold. Pick the threshold from the real shape of such a page: a
   laboratory header plus a caption is a few hundred characters, a read page is a thousand and up.
   State the number as a named constant with a comment saying what it separates.
3. `renderPdfPagesToImages(bytes, options?)` accepts explicit page numbers and renders exactly
   those, keeping every existing bound (`MAX_DOCUMENT_IMAGE_SOURCE_BYTES`,
   `MAXIMUM_DOCUMENT_IMAGE_PAGES`, pixel caps) and returning `pageNumber` as the true page number.
   More candidate pages than the page cap is not an error: render the first N, report the rest.
4. Contracts: `DOCUMENT_PAGE_UNREAD_REASONS` — a closed list, at minimum `image_page_limit`
   (more picture pages than one run may carry) and `vision_unavailable` (the second pass refused or
   failed). Bump `DOCUMENT_CONTRACT_VERSION` and sweep every literal copy in tests and e2e stubs.

**Fixture:** a synthetic PDF with a text page and a picture page, generated by a script beside
`scripts/synthetic-discharge-fixture.mjs`. Synthetic content only.

## Task B — the second pass, merged into one analysis

**Files:** `apps/api/src/processing/document-extraction-processor.ts` (+ test), and whatever small
module the merge deserves — `processing/extraction-merge.ts` is likely, since the processor is
already long.

1. After a successful text pass on a PDF, ask `imageOnlyPages`. If none, nothing changes.
2. Render those pages, call `intelligence.analyze` a second time with `pages: []` and those images.
3. Merge into one `ProcessingExtractionOutput`:
   - pages: the vision page replaces the text page of the same number (its transcription, method
     `codex_vision`, the vision extraction version);
   - `extraction.items`: concatenated, with keys made unique across passes without rewriting any
     fragment or value — a collision is a bookkeeping slip to normalise deterministically, never a
     reason to drop a verified fact;
   - `intelligence`: the text pass's title, category and summaries stay the document's; the vision
     pass contributes only its structured results, bound to their own pages.
4. The second pass is best-effort. A refusal, a provider error, an image-limit error: the text
   pass's output completes the job unchanged and every candidate page it could not read is recorded
   with its closed reason. Pages beyond the page cap get `image_page_limit` even when the pass
   succeeded.
5. Tests: a document with one picture page gains that page's facts and the page stores
   `codex_vision`; a failing second pass leaves the text result and the counts untouched and marks
   the page; more picture pages than the cap marks the remainder; no picture page means exactly one
   `analyze` call (assert the call count — a silent second run costs the household a Codex call).

## Task C — the document says which pages it read

**Files:** the document projection in `apps/api/src/documents/document-service.ts`, its integration
test, `apps/web/app/…` document page components and their pure module, `e2e/`, docs.

1. The document projection carries one entry per page: number, method, whether it was read, and the
   closed reason when it was not.
2. The document page shows it where a reader looks for what the analysis covered — a page that was
   read by vision says so plainly, a page that was not says why in fixed Russian copy from a closed
   code, never a model sentence. No new colour language: this is provenance, not a grade.
3. e2e over the synthetic fixture: a picture page is reported, and its facts appear.
4. `scripts/fake-codex-exec.mjs` must answer the second pass (it already has an `--image` branch;
   keep the two passes distinguishable). `apps/api/test/synthetic-intelligence.ts` likewise.
5. Docs: CLAUDE.md's «Document intelligence provider» and «Domain invariants» paragraphs,
   `docs/architecture.md`'s reading of text-versus-images, `docs/api.md` for the projection.
