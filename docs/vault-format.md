# Veylta Vault v1

`veylta-vault/v1` is the portable, provider-neutral record selected and owned
by the user. A vault may live in a local directory or a directory synchronized
by a cloud-drive desktop client. The directory itself is the source of truth;
SQLite, IndexedDB, and bridge caches are rebuildable indexes only.

## Layout

```text
Veylta Vault/
  vault.json
  profiles/
    <profile-id>/
      profile.json
      documents/
        <document-id>/
          manifest.json
          original.<pdf|png|jpg>
          runs/
            <run-id>.json
      reviews/
        <review-id>.json
      observations/
        <observation-id>.json
  agent/
    commands/
      queued/<command-id>.json
      leased/<command-id>.json
      completed/<command-id>.json
      failed/<command-id>.json
    runs/<run-id>.json
  audit/
    events.jsonl
```

All paths stored in JSON use `/` and are relative to the vault root. UUIDs are
generated by Veylta and never derived from names. User-provided filenames are
display metadata only and cannot become path segments.

## Root manifest

```json
{
  "contractVersion": "veylta-vault/v1",
  "vaultId": "10000000-0000-4000-8000-000000000001",
  "createdAt": "2026-08-13T12:00:00.000Z"
}
```

## Immutable document manifest

```json
{
  "contractVersion": "veylta-vault/v1",
  "id": "10000000-0000-4000-8000-000000000002",
  "profileId": "10000000-0000-4000-8000-000000000003",
  "importedAt": "2026-08-13T12:01:00.000Z",
  "mediaType": "application/pdf",
  "byteSize": 1024,
  "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "originalFileName": "synthetic-report.pdf",
  "sourcePath": "profiles/10000000-0000-4000-8000-000000000003/documents/10000000-0000-4000-8000-000000000002/original.pdf"
}
```

An adapter writes the original to a temporary sibling, verifies size and
SHA-256, finalizes it without overwrite, and only then publishes the manifest.
A controlled read verifies the manifest against the returned byte snapshot.

## Agent command

```json
{
  "protocolVersion": "veylta-agent/v1",
  "id": "10000000-0000-4000-8000-000000000004",
  "type": "analyze_document",
  "vaultId": "10000000-0000-4000-8000-000000000001",
  "profileId": "10000000-0000-4000-8000-000000000003",
  "documentId": "10000000-0000-4000-8000-000000000002",
  "sourceSha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "requestedAt": "2026-08-13T12:02:00.000Z"
}
```

The agent may create a new immutable run and move its command to a terminal
directory. It may not mutate the original, an earlier run, a review decision,
or a confirmed observation. A successful result is still a proposal until the
user reviews it.

The PWA creates only a `queued` record after an explicit user action. The
loopback bridge atomically moves it to `leased`, stores only a SHA-256 digest of
the lease token in the synchronized vault, and moves it to `completed` or
`failed` only when the current lease holder replies. The raw lease token stays
outside the vault. An expired lease is moved back to `queued` with an incremented
attempt count on the next claim.

## Local-only state

The following must stay outside the synchronized vault:

- File System Access handles retained in browser IndexedDB;
- loopback bridge port and random pairing/session tokens;
- OAuth refresh/access tokens and provider credentials;
- Codex credentials, API keys, or billing information;
- absolute filesystem paths and operating-system usernames;
- temporary parser/model caches.

## Conflict and recovery rules

- Originals and versioned results are create-only.
- Mutable indexes are derived and may be rebuilt.
- An existing ID with a different checksum is an integrity conflict, never
  last-writer-wins.
- A stale agent lease is requeued; it does not imply a successful result.
- Unknown major contract versions fail closed.
- Audit events contain selectors and lifecycle outcomes, not document bodies,
  extracted values, credentials, or prompt text.
